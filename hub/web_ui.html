Lobby — public IRC chat


Everyone listed can read this. A message shows the sender's announced name, with their node_id small underneath — the node_id comes from their public key, so someone can't just type another node's name and pass as them. No name set, no sending (see Identity in the left menu).










Set a name first — you can't chat in the lobby until you set a name.


















Identity


This node on node.darknet.ca (Gopher model: the list is open, the gates are per-node). One identity.dat serves both the Hub and the node — the HUB- and NODE- fingerprints below come from the same key. Identity is created on first run; set a name below to announce it. Your node_id comes from your public key, so it can't be spoofed.











Set a name first — you can read the lobby, but you can't chat until you set a name.


Endpoint: the Hub announces without an endpoint, so direct node-to-node connections use the mailbox until an endpoint is set. A peer's card shows its shared endpoint when it has one.






Peers











Private chat


Sysop chat, peer to peer — a separate chatbox queue, so the job poller can never eat these messages.












Files


Public file offers from listed nodes. Each receiver decides its own downloads — there is no central accept step.





Local shared files (regula ledger)


Voices stored here from the waveform player, each with a signed ledger event. Publish one to list it as a public file offer.




Ledger — latest block events


Every session, story, ezine, code file, sample, model, and shared file lands here as a signed, chained event. 50MB chunks live in data/blocks/ for node-to-node transfer.








Jobs — use a peer's model, voice, or image queue




















Transfers — node-to-node jobs, tracked


Every text, voice, and image job you send, with its status — like a torrent client. Auto-refreshes every 5 seconds while this page is open; Fetch pulls fresh replies from your mailbox now.













Serving — what this node serves by default


These defaults decide what your node runs when a peer sends it a job, and what your next Announce shares (including a public endpoint for direct connections). Leave the backend blank to keep the poller's command-line default.






A cloud key is stored on disk (0600) so this node can serve while you are away. Only set it if you mean it — switching back to a local backend deletes the stored key.




Shared on your next Announce so peers that can reach it may connect direct; peers behind NAT still use the mailbox relay.








Poller




















Stories & Storyboard


Context stays within the configured window. Total output grows on disk, to 256k tokens and beyond. Writing is resumable — if it stops, write again and it continues at the next block.























Ezines — for darknet.ca subscribers


An ezine is a collection: cover + table of contents + pieces (stories and articles). 100 pages = 20,000 words, 300 pages = 60,000 words. Compile exports a single darknet.ca-style HTML file you can post as-is.














Uncensored Code


Ask for code, get it in fenced blocks, save it to data/code/ — and it is embedded into vector memory, so future code questions retrieve your own patterns.












Library Search — EmbeddingGemma, full use


One vector DB for everything: chat, story blocks, ezine pieces, code, samples, PDFs. Search it by meaning, not keywords.











Memory


Embed model runs by default. Every chat (local or cloud) is embedded and saved here, and relevant memories are pulled into the next answer when “Use memory” is on.













Samples & PDFs


Drop .txt/.md files in data/samples/, or upload a PDF here (e.g. a travel guide to Italy). Text is extracted, chunked, and embedded with EmbeddingGemma-2. Samples are style/fact inspiration only — never copied verbatim into a story, unless they are facts you asked to use (like travel facts from an ingested guide).















Settings & API Test


Keys are stored in your browser only (localStorage) and sent with each cloud request. The server never writes them to disk. You can also set OPENROUTER_API_KEY / NVIDIA_API_KEY in WSL instead.

Models — Hugging Face


Browse a collection or a single repo and download GGUF files into models/. Downloading a model does not switch the active chat model — pick it in Chat after it lands.





The token is sent with this request only. It is never written to disk, never logged, and never returned by the server. Public collections and repos need no token.










GPU memory required is an ESTIMATE: file size × 1.2 (weights + ~20% overhead allowance for KV cache / context) — not measured. Quantization is parsed from the filename; a dash means the API gave no size or no known quant token — never a fabricated number.
